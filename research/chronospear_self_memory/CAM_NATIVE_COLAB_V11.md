# CAM-Native V1.1 LoRA Training on Google Colab

Research-only workflow for training the CAM-native Qwen3-0.6B V1.1 ontology-literacy LoRA adapter on a hosted NVIDIA GPU.

## Experimental control

V1.1 keeps the original V1 synthetic curriculum and compact 813-character runtime system prompt, then adds the ontology-literacy supplement generated by `cam_native_dataset_v11.py`.

Expected generated data:

```text
train_examples=816
eval_examples=232
v1_base_train_examples=704
ontology_train_examples=112
ontology_fraction=13.7%
ontology_skills=7
system_prompt_characters=813
```

The trainer and hyperparameters remain the same as V1. Only the dataset and output adapter name change.

## Local machine: prepare upload bundle

From `research/chronospear_self_memory` after generating `cam_native_data_v11`:

```bash
rm -f cam_native_training_bundle_v11.zip
zip -r cam_native_training_bundle_v11.zip \
  cam_native_train.py \
  requirements-cam-native.txt \
  cam_native_data_v11/train.jsonl \
  cam_native_data_v11/eval.jsonl
```

## Colab: GPU check

Use **Runtime -> Change runtime type -> GPU** and verify CUDA before training:

```python
import torch
print(torch.cuda.is_available())
print(torch.cuda.get_device_name(0) if torch.cuda.is_available() else "NO CUDA GPU")
```

Stop if CUDA is `False`. Do not use `--allow-cpu` in Colab.

## Upload and unpack

Upload `cam_native_training_bundle_v11.zip` with the Files pane, then run:

```bash
!unzip -o cam_native_training_bundle_v11.zip -d cam_native_training_v11
%cd cam_native_training_v11
```

Install dependencies and remove the stale optional torchao package if present:

```bash
!python -m pip install -q -r requirements-cam-native.txt
!python -m pip uninstall -y torchao
```

Restart the runtime only if Colab explicitly requests it. If restarted, return to the unpacked directory before continuing.

## Smoke training

```bash
!python cam_native_train.py \
  --train cam_native_data_v11/train.jsonl \
  --eval cam_native_data_v11/eval.jsonl \
  --output-dir cam_native_adapter_v11_smoke \
  --smoke
```

A valid smoke run should report CUDA enabled and the V1.1 dataset counts.

## Full V1.1 training

```bash
!python cam_native_train.py \
  --train cam_native_data_v11/train.jsonl \
  --eval cam_native_data_v11/eval.jsonl \
  --output-dir cam_native_adapter_qwen3_0_6b_v11
```

Keep the default V1 training settings unchanged for the first V1 vs V1.1 comparison:

- model: `Qwen/Qwen3-0.6B`
- LoRA rank: 16
- target modules: all linear layers
- epochs: 3
- learning rate: `1e-4`
- batch size: 1
- gradient accumulation: 8
- maximum sequence length: 1024
- assistant-only loss

The adapter directory is already ignored by Git.

## Evaluation order

First evaluate held-out V1.1 synthetic cases. Then convert the adapter to GGUF and compare against the existing V1 llama.cpp fingerprint tests with the same compact runtime prompt and rich initial packet.

Primary untouched ChronoSpear probe:

```text
What evidence do we have that Packet #1 can stay question-agnostic?
```

The experiment succeeds only if evidence judgment improves without breaking the known V1 semantic/protocol behaviors.
